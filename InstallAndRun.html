Image Gallery — Install & Run Guide

This document explains how to install the image gallery website on a new machine, start the backend and frontend servers, and where the data lives. The application has two parts:

Backend — Django + SQLite REST API, admin interface, database, media serving. Runs on port 8000.
Frontend — React + Vite The website users interact with: gallery grid, search, filters, editing, import/export. Runs on port 5173 in development.

Prerequisites

Install these tools before you begin:

  • Git — to clone the repository
  • Python 3.x — for the Django backend
  • Node.js + npm — for the React frontend (nodejs.org, LTS version recommended)
Step 1 — Clone the repository
git clone https://github.com/radumanolescu/image_gallery.git
cd image_gallery
Step 2 — Install backend dependencies

Create a Python virtual environment and install the packages listed in backend/requirements.txt:

cd backend
python -m venv venv

# Activate the virtual environment:
venv\Scripts\activate      # Windows (Command Prompt)
venv\Scripts\Activate.ps1  # Windows (PowerShell)
source venv/bin/activate   # macOS / Linux

pip install -r requirements.txt
Step 3 — Set up the database

Still inside backend/ with the virtual environment activated:

# Create the database tables
python manage.py migrate

# Load image metadata from the TXT files into the database
python manage.py load_metadata

# Optional: verify the import (should report all records matching)
python manage.py validate_metadata

# Create an admin account (you choose username/password)
python manage.py createsuperuser
Step 4 — Install frontend dependencies
cd ..\frontend      # Windows; use cd ../frontend on macOS/Linux
npm install

Running the Website

Both servers must be running at the same time. Use two terminals:

Terminal 1 — Backend
cd backend
venv\Scripts\activate          # (source venv/bin/activate on macOS/Linux)
python manage.py runserver

Starts the Django server on http://localhost:8000

Terminal 2 — Frontend
cd frontend
npm run dev

Starts the Vite dev server and prints the local URL — normally http://localhost:5173/ (if that port is busy it picks the next one, e.g. 5174 — use the URL Vite prints).

Why two servers? The Vite dev server transparently forwards /api and /media requests to the Django backend, so to your browser everything looks like one site. Always open the site via localhost (not 127.0.0.1) so login cookies work correctly.

URLs

URL Audience What it is
http://localhost:5173/ General users The image gallery website — browse, search, filter, preview images
http://localhost:5173/login Editors / admins Sign in to enable metadata editing, bulk edit, and import
http://localhost:8000/admin/ Administrators Django admin — manage users and metadata records directly
http://localhost:8000/api/images/ Developers REST API endpoint (JSON)
http://localhost:8000/api/docs/ Developers Interactive API documentation (Swagger UI)

Where the Data Is Stored

Data Location Notes
Image metadata (titles, prices, inventory, keywords, ...) backend/db.sqlite3 A single SQLite database file — the table is image_metadata, keyed by image file name. Back it up by copying this one file.
Image files (.JPG) static/images/ Served by the backend at /media/
Legacy metadata TXT files static/images/*.txt The original per-image metadata files. They are the source for load_metadata and remain untouched — keep them as a backup.
Important when moving to a new machine: the image files, TXT metadata files, and the SQLite database are not stored in Git — they are listed in .gitignore. After cloning, you must copy them separately from the old machine:
  • Copy static/images/ (all .JPG and .txt files) to the new clone
  • Either copy backend/db.sqlite3 directly, or run python manage.py migrate then python manage.py load_metadata to rebuild it from the TXT files
Verify the result with python manage.py validate_metadata.

User Accounts

Users are created through the admin interface or with python manage.py createsuperuser. Anonymous visitors can browse and search; only logged-in users can edit metadata, bulk edit, or import files.

Troubleshooting

Symptom Fix
Frontend shows "Failed to load images" Make sure the backend is running on port 8000 — the frontend proxies /api to it
Login works but edits fail Browse via localhost, not 127.0.0.1 — cookies are host-specific
Port 5173 or 8000 already in use Another server instance is running — close it, or use the alternate port Vite/Django prints
Images load but no metadata Run python manage.py load_metadata in backend/ with the venv activated
python not found Activate the virtual environment first (venv\Scripts\activate), or use the full path venv\Scripts\python.exe

Verifying the Installation

  • cd backend && python manage.py test gallery — 89 backend tests
  • cd frontend && npm test — 28 frontend tests
  • Open http://localhost:5173/ — you should see the image grid populate
Quick summary: clone → create venv & pip install -r requirements.txt → migrate → copy static/images/ → load_metadata → createsuperuser → npm install → run manage.py runserver and npm run dev → open http://localhost:5173/
